## 1. Lecture Map

A **binomial heap** is a collection of heap-ordered trees. The lazy version used in this lecture postpones most structural work until the minimum element is removed.

This gives the following trade-off:

- `insert` simply adds a one-node tree.
- `meld` simply joins two root lists.
- `removeMin` performs the delayed work by combining trees of equal degree.

> **Lecture flow:** represent a heap as a circular list of min trees -> perform constant-time insertion and melding -> see why a basic `removeMin` can be linear -> consolidate equal-degree trees -> use binomial-tree sizes and amortized analysis to obtain the final bounds.

<img src="./assets/lecture06-complexity-comparison.png" alt="Actual and amortized complexity comparison for leftist trees and binomial heaps" style="zoom:50%;" />

For the lazy binomial heap studied here:

| Operation | Actual worst case | Amortized |
| --- | ---: | ---: |
| Insert | $O(1)$ | $O(1)$ |
| Meld | $O(1)$ | $O(1)$ |
| Remove minimum | $O(n)$ | $O(\log n)$ |

The linear actual bound for `removeMin` does not contradict its logarithmic amortized bound. One removal may be expensive, but the many cheap insertions and melds that created its work can pay for it.

## 2. Structure and Representation



<img src="./assets/image-20260918164905167.png" alt="image-20260918164905167" style="zoom:50%;" />

A **min tree** is a rooted tree satisfying the min-heap property:

$$
\text{key(parent)}\leq\text{key(child)}
$$

Therefore, the smallest element in a min tree is stored at its root. A min binomial heap is a collection of these min trees.

Each tree node stores:

<img src="./assets/image-20260918165708820.png" alt="image-20260918165708820" style="zoom:50%;" />

- its data or key;
- its degree, which is its number of children;
- a pointer to one child;
- a sibling pointer used to connect nodes in a circular list.



The roots of all trees are held in one circular linked list. The children of a node are also represented by a circular sibling list. A heap pointer identifies the root containing the overall minimum key.

<img src="./assets/image-20260918165727403.png" alt="image-20260918165727403" style="zoom:50%;" />

This representation is important because circular lists can be concatenated in $O(1)$ time when suitable list pointers are available. It is the reason insertion, melding, and reinserting the removed root's children can avoid traversing all nodes.

 

**Two levels of order must not be confused:**

- Within every tree, parent keys obey the min-heap property.
- The top-level roots do not have to be sorted by key or degree.

The separate minimum pointer gives direct access to the smallest root even though the root list is unsorted.

## 3. Constant-Time Insert and Meld

### **Insertion**

<img src="./assets/image-20260918170621877.png" alt="image-20260918170621877" style="zoom: 50%;" />

<img src="./assets/image-20260918170901517.png" alt="image-20260918170901517" style="zoom:50%;" />

To insert key $x$:

1. Create a one-node min tree containing $x$.
2. Add it to the circular list of roots.
3. Update the minimum pointer if $x$ is smaller than the current minimum.

```text
insert(H, x):
    T = one-node tree containing x

    if H is empty:
        H.rootList = T
        H.min = T
    else:
        splice T into H.rootList
        if x < H.min.key:
            H.min = T
```

All pointer changes and the comparison take constant time:

$$
T_{insert}(n)=O(1)
$$



Notice that insertion does **not** immediately combine the new tree with another tree of the same degree. This delayed consolidation is what makes the operation worst-case $O(1)$.



### **Meld**

To meld heaps $H_1$ and $H_2$:

1. Concatenate their circular root lists.
2. Set the new minimum pointer to the smaller of the two old minima.

<img src="./assets/image-20260918170923860.png" alt="image-20260918170923860" style="zoom:50%;" />

<img src="./assets/image-20260919171857334.png" alt="image-20260919171857334" style="zoom:50%;" />



```text
meld(H1, H2):
    if one heap is empty:
        return the other heap

    concatenate H1.rootList and H2.rootList
    H.min = the smaller of H1.min and H2.min
    return H
```

No tree is traversed or consolidated, so:

$$
T_{meld}(n)=O(1)
$$

<img src="./assets/lecture06-meld.png" alt="Melding two binomial heaps by concatenating their root lists" style="zoom: 33%;" />

> This is an advantage over leftist trees, whose insert and meld operations take $O(\log n)$ time.

## 4. Removing the Minimum

The minimum pointer immediately identifies the tree whose root must be removed. The basic procedure is:

1. Remove the minimum root and its tree from the top-level circular list.
2. Delete that root, leaving each of its child subtrees as a separate min tree.
3. Concatenate the list of these child trees with the heap's remaining root list.
4. Scan all top-level roots and reset the minimum pointer.

<img src="./assets/image-20260919172539105.png" alt="image-20260919172539105" style="zoom:50%;" />

<img src="./assets/image-20260919174822060.png" alt="image-20260919174822060" style="zoom:67%;" />

> <img src="./assets/image-20260919175433736.png" alt="image-20260919175433736" style="zoom:50%;" />
>
> Therefore we can use this method to remove the min without traversing through the entire upper level.
>
> ![image-20260919175449326](./assets/image-20260919175449326.png)

<img src="./assets/image-20260919182341806.png" alt="image-20260919182341806" style="zoom:50%;" />

The list splices take $O(1)$ time. The expensive step is finding the new minimum.

<img src="./assets/image-20260919182328796.png" alt="image-20260919182328796" style="zoom:50%;" />

If there are $s$ trees in the top-level list, the scan costs:

$$
O(s)
$$

Because lazy insertions can create $n$ separate one-node trees, it is possible that $s=n$. Therefore, the actual worst-case time is:

$$
T_{removeMin}(n)=O(n)
$$

<img src="./assets/image-20260919182400437.png" alt="image-20260919182400437" style="zoom:50%;" />

The scan would be wasteful if the heap were left with many trees. The enhanced operation performs **consolidation** during this traversal, reducing the number of roots for future operations.

## 5. Consolidation by Degree

Root level එකටම nodes n ප්‍රමාණයම එන එක වලක්වන්න කරන මෙතොඩ් එකක්. නැත්ත්න් නෝර්මලි නෝඩ් ඉන්සර්ට් කරන්න ගියාම එකෙන් එකට දාගෙන දාගෙන යද්දි ඔක්කොම root level circular linked list එකටනේ එන්නේ.

Consolidation (ඒකාබද්ධ කිරීම) combines roots with equal degree. A temporary **tree table** is indexed by degree, *so table position $d$ can hold at most one tree of degree $d$.*

**Linking two equal-degree trees**

Suppose $T_1$ and $T_2$ both have degree $d$.

- Compare their root keys.
- The tree with the smaller root remains the parent tree.
- Make the other root a child of the smaller root.
- The combined tree has degree $d+1$.

The link changes only a constant number of pointers, so one link costs $O(1)$.

If the table already contains a degree-$(d+1)$ tree, another collision occurs and linking continues. This is exactly like carrying during binary addition:

```text
one degree-d tree + one degree-d tree
        -> one degree-(d+1) tree
```

**Consolidation procedure**

```text
consolidate(rootList):
    set every entry of degreeTable to empty

    for each tree T in rootList:
        d = T.degree

        while degreeTable[d] is not empty:
            U = degreeTable[d]
            degreeTable[d] = empty
            T = link(T, U)
            d = d + 1

        degreeTable[d] = T

    rebuild the circular root list from nonempty table entries
    find the smallest root while rebuilding the list
    set the heap's minimum pointer to that root
```

At the end, there is at most one tree of each degree.



### **Enhanced `removeMin`**

The complete operation is therefore:

```text
removeMin(H):
    if H is empty:
        fail

    z = H.min
    remove z's tree from H.rootList
    promote z's child subtrees to top-level trees
    concatenate those trees with H.rootList
    consolidate(H.rootList)
    return z.key
```

<img src="./assets/image-20260920112607715.png" alt="image-20260920112607715" style="zoom:50%;" />

The temporary table does not sort keys. Its purpose is only to detect equal degrees. Heap order is preserved by making the smaller of two roots the parent during every link.

## 6. Binomial Trees and the Degree Bound

<img src="./assets/image-20260920113834995.png" alt="image-20260920113834995" style="zoom:50%;" />

<img src="./assets/image-20260920113633059.png" alt="image-20260920113633059" style="zoom:50%;" />

<img src="./assets/image-20260920114900218.png" alt="image-20260920114900218" style="zoom:50%;" />

A **binomial tree** $B_k$ is defined recursively:

- $B_0$ is a single node.
- $B_k$ is formed by linking two copies of $B_{k-1}$, making one root a child of the other.

*Equivalently*, the root of $B_k$ has degree $k$, and its children are roots of:
$$
B_0,B_1,\ldots,B_{k-1}
$$

<img src="./assets/image-20260920114914892.png" alt="image-20260920114914892" style="zoom:50%;" />

<img src="./assets/image-20260920114942824.png" alt="image-20260920114942824" style="zoom:50%;" />

<img src="./assets/image-20260920114954192.png" alt="image-20260920114954192" style="zoom:50%;" />

Let $N_k$ be the number of nodes in $B_k$. From the recursive construction:

$$
N_0=1
$$

$$
N_k=2N_{k-1}
$$

Expanding the recurrence gives:

$$
N_k=2^k
$$

Thus a binomial tree of degree $k$ contains $2^k$ nodes. If the complete heap contains $n$ nodes, then:

$$
2^k\leq n
$$

Taking base-2 logarithms:

$$
k\leq\left\lfloor\log_2 n\right\rfloor
$$

Therefore, the maximum possible tree degree is $O(\log n)$. After consolidation there can be at most one tree for each degree from 0 through $\lfloor\log_2 n\rfloor$, so the root list contains at most:

$$
\left\lfloor\log_2 n\right\rfloor+1
$$

trees.



**Connection to binary representation**

After consolidation, a degree-$k$ tree contributes exactly $2^k$ nodes. Consequently, *the degrees present in the root list correspond to the 1 bits in the binary representation of $n$.*

For example:

$$
13=8+4+1=2^3+2^2+2^0
$$

A fully consolidated 13-node heap therefore contains trees of degrees 3, 2, and 0.

The lazy heap may temporarily contain several trees of the same degree after insertions or melds. The binary-representation property becomes exact again after consolidation.

> EXTRA!
>
> ## 7. Why the Amortized Removal Cost Is Logarithmic
>
> Let $r$ be the number of top-level trees and choose a potential proportional to that number:
>
> $$
> \Phi(H)=\alpha r
> $$
>
> where $\alpha$ is a sufficiently large positive constant.
>
> **Insertion** adds one new root. Its actual cost is constant and its potential increases by $alpha$:
>
> $$
> \hat c_{insert}=O(1)+\alpha=O(1)
> $$
>
> **Meld** joins two root lists without changing the total number of roots across the two input heaps. Its actual and amortized costs are both $O(1)$.
>
> **Removal** may begin with many roots. Let the removed minimum root have degree $d$ and let $r'$ be the number of roots after consolidation.
>
> - Removing the root and promoting its children produces $r-1+d$ roots before consolidation.
> - Examining roots and performing links costs $O(r+d)$.
> - Because $d=O(\log n)$ and the consolidated heap has at most one tree per degree, $r'=O(\log n)$.
> - The potential change is $\alpha(r'-r)$, which is strongly negative when many accumulated roots are combined.
>
> The amortized cost is:
>
> $$
> \hat c_{removeMin}
> =c_{removeMin}+\Phi_{after}-\Phi_{before}
> $$
>
> With a sufficiently large $alpha$, the decrease caused by replacing many old roots with only $O(\log n)$ roots pays for the scan and links. The remaining work depends only on $d$ and $r'$, both of which are $O(\log n)$. Hence:
>
> $$
> \hat c_{removeMin}=O(\log n)
> $$
>
> The main idea is that every cheap insertion can create one extra root and therefore stores potential. A later expensive removal consumes that stored potential while combining the roots.
>

**Final complexity summary**

| Operation | Why | Actual worst case | Amortized |
| --- | --- | ---: | ---: |
| Find minimum | Follow the stored minimum pointer | $O(1)$ | $O(1)$ |
| Insert | Add a singleton root | $O(1)$ | $O(1)$ |
| Meld | Concatenate two circular root lists | $O(1)$ | $O(1)$ |
| Link equal-degree trees | Compare roots and change pointers | $O(1)$ | $O(1)$ |
| Remove minimum | May scan and consolidate many roots | $O(n)$ | $O(\log n)$ |

## 8. Quick Revision

1. A min binomial heap is a collection of heap-ordered binomial trees.
2. The roots are stored in a circular list, with a pointer to the minimum root.
3. Lazy insertion adds a one-node tree without consolidation, so it costs $O(1)$.
4. Meld concatenates two root lists and compares their minima, so it costs $O(1)$.
5. A basic `removeMin` can take $O(n)$ because the root list may contain $n$ trees.
6. Consolidation uses a degree-indexed table and repeatedly links equal-degree trees.
7. Linking two degree-$d$ trees creates one degree-$(d+1)$ tree, like a carry in binary addition.
8. A binomial tree $B_k$ has degree $k$ and $2^k$ nodes.
9. The maximum degree and the number of roots after consolidation are both $O(\log n)$.
10. The number of roots is a natural potential, proving an amortized `removeMin` cost of $O(\log n)$.
